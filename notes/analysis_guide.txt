================================================================================
PHISHING ANALYSIS & SOC LOG CORRELATION FIELD GUIDE
================================================================================
Target Role: L1 / Associate SOC Analyst (Sutherland & Enterprise Operations)
Focus: Phishing Triage, Log Correlation, and Incident Containment

--------------------------------------------------------------------------------
PART 1: THE 3 CORE PHISHING ARCHETYPES
--------------------------------------------------------------------------------
In real enterprise environments, 98% of all phishing attacks boil down to three
distinct operational archetypes:

1. THE CREDENTIAL HARVESTER (Link-Based)
   - Examples: Fake Microsoft 365, DocuSign, or HR password-reset notifications.
   - The Playbook:
     * Locate and extract the URL from the message body.
     * Detonate/trace redirect hops in an isolated throwaway container.
     * Check domain age, registrar reputation, and DNS resolution.

2. THE EVASIVE ATTACHMENT (File-Based)
   - Examples: Weaponized/tampered PDFs (Banco do Brasil image lure) or DOCX/ZIP files.
   - The Playbook:
     * Never open the file in a standard host application.
     * Calculate SHA-256 hash and check threat intelligence reputation.
     * Inspect low-level structure: extract image bitmaps (pdfimages), check object
       stream URIs (qpdf), and inspect archive headers for padding anomalies (unzip).

3. BUSINESS EMAIL COMPROMISE / BEC (Text-Only)
   - Examples: Fake CEO/CFO wire transfer requests or vendor bank detail changes.
   - The Playbook:
     * No links or attachments to detonate.
     * Inspect display name spoofing vs. authentic envelope sender.
     * Verify SPF/DKIM cryptographic alignment.
     * Check for mismatched 'Reply-To' addresses directing replies to personal
       mailboxes (Gmail, Yahoo, Proton).

--------------------------------------------------------------------------------
PART 2: THE 4-STEP MENTAL CHECKLIST
--------------------------------------------------------------------------------
When a suspicious email alert arrives in your queue, ask these 4 questions in order:

  1. WHO SENT IT?
     └─ Do 'From', 'Return-Path', and 'Reply-To' match?
     └─ Did SPF, DKIM, and DMARC pass, fail, or encounter permanent errors?
     └─ Note: A "pass" proves sender identity, NOT benign intent!

  2. WHAT IS THE LURE?
     └─ Is it creating artificial urgency ("Account locked", "Tax refund", "Invoice overdue")?
     └─ Does the branding match the authentic sender organization?

  3. HOW IS IT DELIVERED?
     └─ Is the delivery mechanism an embedded Link or a File Attachment?

  4. WHAT IS THE DESTINATION?
     └─ Link: Where does the redirect chain terminate? Is it abusing cloud PaaS (Vercel, Azure)?
     └─ Attachment: Does it drop a payload, launch macros, or hide a clickable URL?

--------------------------------------------------------------------------------
PART 3: THE 3-COMMAND FORENSIC TOOLKIT
--------------------------------------------------------------------------------
For any raw .eml file, these three commands answer 90% of your triage questions:

  # 1. Inspect sender identity and authentication results:
  grep -iE '^(From|Reply-To|Return-Path|Authentication-Results):' sample.eml

  # 2. Extract embedded links:
  grep -ioE 'https?://[^ "]+' sample.eml | head -10

  # 3. Check for attached payloads:
  grep -i 'filename=' sample.eml

--------------------------------------------------------------------------------
PART 4: THE 3-DAY MUSCLE MEMORY TRAINING PLAN
--------------------------------------------------------------------------------
You have 10,000+ real samples stored in `~/phish-lab/samples/phishing_pot/email/`.
Build automated muscle memory using this simple routine:

  • Day 1: Pick 2 random .eml files. Run the 3 commands. Answer the 4 questions in
           a 5-bullet scratch note.
  • Day 2: Pick 2 more random files. Identify whether they are Link, Attachment, or BEC.
  • Day 3: Pick 2 more. Trace the links or extract hashes without looking at notes.

By the 5th email, triage will become an instinctual, 3-minute workflow.

--------------------------------------------------------------------------------
PART 5: EMAIL ANALYSIS VS. LOG ANALYSIS
--------------------------------------------------------------------------------
Analogy: In a SOC, Email Analysis finds the bullet; Log Analysis checks who got shot.

Feature                | Email Analysis                         | Log Analysis
-----------------------|----------------------------------------|----------------------------------------
What you analyze       | A single communication artifact        | A continuous stream of system events
                       | (.eml, .msg, PDF, DOCX).               | (Web Proxies, Firewalls, Windows Logs).
The core question      | "Is this message malicious, who sent   | "Did this attack succeed, which hosts
                       | it, and what is the payload?"          | were impacted, and what happened next?"
Primary toolset        | Sandboxes, text editors, header tools  | SIEMs (Wazuh, Splunk, Sentinel),
                       | (MXToolbox), VirusTotal, CyberChef.    | EDR dashboards, regex/log parsers.
Primary output         | IOCs (malicious domains, sender emails,| Timelines, Blast Radius, Compromised
                       | IP addresses, file hashes).            | hosts, and containment action scopes.

--------------------------------------------------------------------------------
PART 7: THE 3 CRITICAL LOG SOURCES IN A SOC
--------------------------------------------------------------------------------
1. PROXY / WEB GATEWAY LOGS (Squid, Zscaler, Palo Alto):
   - Confirms if an employee browsed to the phishing URL.
   - HTTP 200 = User successfully loaded the page (potential credential harvest).
   - HTTP 403 = Gateway blocked the request (attack thwarted).

2. DNS QUERY LOGS:
   - Verifies if any internal host performed a name lookup for the attacker domain,
     even if the web connection timed out.

3. ENDPOINT & AUTHENTICATION LOGS (Active Directory, Windows Security Events 4624/4625):
   - Detects if stolen credentials were used to authenticate to corporate VPNs,
     SSO, or Microsoft 365 from anomalous geographic locations shortly after delivery.

--------------------------------------------------------------------------------
PART 8: MASTER SUTHERLAND INTERVIEW ANSWER
--------------------------------------------------------------------------------
Question: "What is the relationship between email security and log analysis?"

Answer:
"Email analysis is how we deconstruct the initial lure and extract high-fidelity
Indicators of Compromise—such as lookalike sender domains, weaponized attachment
hashes, and credential harvesting landing links.

Log analysis is how we determine the blast radius and operational impact. I take
those extracted IOCs and query our SIEM proxy, DNS, and authentication logs to
verify whether any internal workstation established outbound connectivity or if
compromised credentials were used for unauthorized access. 

Email analysis identifies the threat; log analysis confirms containment and informs
remediation."
